# Elitea Community

Welcome to the public community repository for **Elitea**.

This repository is the central place for public users to:

- report **bugs**
- request **features**
- propose **improvements**
- ask **questions**
- share **feedback** and ideas with the community

## Purpose of this repository

Use this repository if you want to help improve Elitea by sharing product feedback, reporting issues, or participating in public discussions.

This repository is intended for **community intake and discussion**. The Elitea Support/Core team reviews reports and discussions here, triages actionable items through the public **Elitea Community Triage** project, and may copy relevant items into internal planning systems for prioritization and delivery tracking.

## Use this repository for

### Issues
Open an issue when you want to:

- report a reproducible bug
- request a new feature
- propose an improvement that should be tracked formally
- report a documentation problem or missing guidance

### Discussions
Use Discussions when you want to:

- ask usage questions
- share ideas before opening a formal feature request
- discuss workflows, best practices, or product behavior
- provide general feedback
- share examples, use cases, or community suggestions

## Do not use this repository for

Please do **not** use this repository for:

- security vulnerability disclosures
- private customer data, credentials, tokens, or internal system details
- urgent production incidents requiring immediate private support
- confidential roadmap or internal planning discussions

For security vulnerabilities, use this repository’s **GitHub private vulnerability reporting** flow from the **Security** tab. See [SECURITY.md](./SECURITY.md) for details.

## How to report a bug

1. Search existing issues and discussions first to avoid duplicates.
2. Open the **Bug Report** issue template.
3. Include:
   - a clear summary
   - steps to reproduce
   - expected behavior
   - actual behavior
   - environment details
   - screenshots or logs, if available
4. Remove sensitive data before posting.
5. If the issue is actually security-sensitive, do **not** open a public issue; use the repository’s private vulnerability reporting flow instead.

## How to request a feature

1. Search existing issues and discussions first.
2. Open the **Feature Request** issue template.
3. Explain:
   - the problem you want to solve
   - the proposed solution
   - the user or business value
   - any alternatives considered
   - acceptance criteria, if possible

## How to use Discussions

Use Discussions for:

- **Q&A** — “How do I do X?”
- **Ideas** — early suggestions and brainstorming
- **Feature Proposals** — larger concepts that may benefit from community input before becoming tracked issues
- **Troubleshooting** — help with setup, configuration, or usage
- **Feedback** — product impressions and improvement suggestions
- **Show and Tell** — examples, workflows, and success stories

## What happens after you post

The Elitea Support/Core team reviews incoming issues and discussions.

Issues and requests may be:

- labeled and classified
- added to the **Elitea Community Triage** project
- moved through triage and backlog states
- accepted for implementation
- closed as duplicate, invalid, out of scope, or not planned
- copied into internal planning systems for deeper prioritization and execution tracking

Opening an issue or discussion does **not** guarantee implementation.

## How the project board is used

Public issues are tracked in the **Elitea Community Triage** project. Typical workflow states include:

- `New`
- `To triage`
- `Backlog`
- `Accepted`
- `In progress`
- `In Testing`
- `Done`

See [PROJECTS.md](./PROJECTS.md) for more details about how the project works.

## Support expectations

We aim to review new submissions as capacity allows. Response times may vary depending on volume, severity, and team availability.

Current guidance:

- initial triage target: **within 5 business days**
- critical bug acknowledgement target: **within 2 business days** when clearly identified and reproducible

These are targets, not guarantees.
