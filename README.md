# Elitea Community

Welcome to the public community repository for **Elitea**.

This repository is the central place for public users to:

- Report **bugs**
- Request **features**
- Propose **improvements**
- Ask **questions**
- Share **feedback** and discuss ideas with the community

## Purpose of this repository

Use this repository if you want to help improve Elitea by sharing product feedback, reporting issues, or participating in public discussions.

This repository is intended for **community intake and discussion**. The Elitea Support/Core team reviews reports and discussions here, and relevant items may be copied into internal planning systems for prioritization and release tracking.

## Use this repository for

### Issues
Open an issue when you want to:

- Report a reproducible bug
- Request a new feature
- Propose an improvement that should be tracked formally

### Discussions
Use Discussions when you want to:

- Ask usage questions
- Share ideas before opening a formal feature request
- Discuss workflows, best practices, or product behavior
- Provide general feedback
- Share examples or use cases with the community

## Do not use this repository for

Please do **not** use this repository for:

- Sensitive security vulnerability reports
- Private customer data, credentials, tokens, or internal system details
- Urgent production incidents requiring immediate support
- Internal team planning or confidential roadmap discussions

For security issues, see [SECURITY.md](./SECURITY.md).

## How to report a bug

1. Search existing issues first to avoid duplicates.
2. Open the **Bug Report** issue template.
3. Include:
   - a clear summary
   - steps to reproduce
   - expected behavior
   - actual behavior
   - environment details
   - screenshots or logs, if available
4. Remove sensitive data before posting.

## How to request a feature

1. Search existing issues and discussions first.
2. Open the **Feature Request** issue template.
3. Explain:
   - the problem you want to solve
   - the proposed solution
   - the user or business value
   - any alternatives considered
   - acceptance criteria, if possible

## How to use Discussions

Use Discussions for:

- **Q&A**: “How do I do X?”
- **Ideas**: early suggestions and brainstorming
- **Feature Proposals**: larger concepts that may need community input before becoming issues
- **Troubleshooting**: help with setup, configuration, or usage
- **Feedback**: product impressions and improvement suggestions
- **Show and Tell**: examples, workflows, and success stories

## What happens after you post

The Elitea Support/Core team will review incoming issues and discussions.

Possible outcomes include:

- Requesting more information
- Confirming and labeling the item
- Closing the issue as duplicate, invalid, or out of scope
- Converting discussion into a tracked request
- Copying accepted items into internal planning repositories for prioritization

Opening an issue or discussion does **not** guarantee implementation.

## Support expectations

We aim to review new submissions as capacity allows. Response times may vary depending on volume, severity, and team availability.

Recommended wording:
- Initial triage target: **within 5 business days**
- Critical bug acknowledgement target: **within 2 business days**, when clearly identified and reproducible

Adjust these targets to match your actual operating model before publishing.
