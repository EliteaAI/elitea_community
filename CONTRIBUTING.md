# Contributing to Elitea Community

Thank you for helping improve **Elitea**.

This repository is the public community space for bug reports, feature requests, discussions, and feedback.

## Before you post

Please:

- search existing issues first
- search existing discussions first
- use the correct channel for your topic
- avoid posting secrets, tokens, private customer data, or sensitive internal details
- review the [Code of Conduct](./CODE_OF_CONDUCT.md)

## Choose the right channel

### Use **Issues** for

- reproducible bugs
- formal feature requests
- actionable product improvements
- documentation issues that should be tracked formally

Open issues here:

- https://github.com/EliteaAI/elitea_community/issues

### Use **Discussions** for

- questions
- troubleshooting
- early-stage ideas
- product feedback
- workflow suggestions
- community sharing

Start a discussion here:

- https://github.com/EliteaAI/elitea_community/discussions

## Reporting bugs

Please use the **Bug Report** template and include:

- a clear summary
- reproduction steps
- expected behavior
- actual behavior
- environment details
- screenshots or logs if available
- any workaround, if one exists

Please redact sensitive data before posting.

If the issue may be a **security vulnerability**, do **not** open a public issue. Use the repository’s **Security** tab and select **Report a vulnerability**. See [SECURITY.md](./SECURITY.md).

## Requesting features

Please use the **Feature Request** template and include:

- the problem you want to solve
- the proposed solution
- user or business value
- a realistic use case
- any alternatives considered
- acceptance criteria if possible

## How triage works

Maintainers review incoming issues and may:

- ask follow-up questions
- apply labels
- classify the affected feature area or integration
- assess severity and priority
- add the item to the **Elitea Community Triage** project
- close items that are duplicate, invalid, out of scope, or not planned

See [PROJECTS.md](./PROJECTS.md) for the public project workflow.

## Labels and status

Labels are used to classify issues, for example:

- `type:*` for issue type
- `feat:*` for product area
- `int:*` for related integration
- `nfr:*` for quality concerns
- `meta:*` for triage context or resolution markers

See [LABELS.md](./LABELS.md) for the full label guide.

The **project board** is used to track workflow state such as:

- `New`
- `To triage`
- `Backlog`
- `Accepted`
- `In progress`
- `In Testing`
- `Done`

## Security issues

Please do **not** report security vulnerabilities in public issues or discussions.

Use the repository’s **Security** tab and select **Report a vulnerability**, or follow the guidance in [SECURITY.md](./SECURITY.md).

## Community standards

By participating, you agree to follow our [Code of Conduct](./CODE_OF_CONDUCT.md).

We welcome respectful disagreement, thoughtful feedback, and constructive discussion.
